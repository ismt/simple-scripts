Сгенерируй документ в формате GitHub Flavored Markdown (GFM) — 
полноценно используя все возможности, которые поддерживает GitHub.

Разрешено и приветствуется:
- Таблицы через | с выравниванием :---:
- Чекбоксы задач: - [ ] и - [x]
- Зачёркивание: ~~текст~~
- Автоссылки на issues/PR: #123, GH-123
- Упоминания пользователей: @username (только если реально нужно 
  уведомить конкретного человека)
- Emoji-коды: :warning:, :rocket:, :white_check_mark:
- Alert-блоки GitHub:
  > [!NOTE]
  > [!TIP]
  > [!IMPORTANT]
  > [!WARNING]
  > [!CAUTION]
- Блоки кода с подсветкой синтаксиса через ```язык
- Диаграммы Mermaid внутри ```mermaid — GitHub рендерит их нативно
- Якоря на заголовки в формате #заголовок-в-нижнем-регистре-с-дефисами 
  (генерируются автоматически GitHub, кастомные {#id} не нужны)
- Вставка изображений и бейджей (shields.io) через ![alt](url)
- HTML-теги, если чего-то не хватает в синтаксисе (GitHub санитизирует 
  опасные теги, но <details>/<summary>, <sub>, <sup>, <br>, <img> 
  с атрибутами width — работают)
- Сворачиваемые блоки:
  <details>
  <summary>Заголовок</summary>
  содержимое
  </details>

НЕ используй:
- Синтаксис {#custom-id} для заголовков (не поддерживается GitHub)
- Сноски в стиле Pandoc с кастомным форматированием (базовые [^1] 
  GitHub поддерживает, но не расширенный синтаксис)
- Директивы MkDocs/Docusaurus (::: note, admonitions в других форматах)

Учитывай, что документ будет открываться ТОЛЬКО на GitHub 
(README, PR-описание, issue, wiki-страница) — не в других 
рендерерах, поэтому GitHub-специфичные фичи использовать можно 
и нужно, если они уместны по смыслу.
