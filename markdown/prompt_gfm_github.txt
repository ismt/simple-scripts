Сгенерируй документ в формате GitHub Flavored Markdown (GFM) — 
полноценно используя все возможности, которые поддерживает GitHub.

Разрешено и приветствуется:
- Таблицы через |. Выравнивание задавай явно: --- (по умолчанию, 
  слева), :--- (слева), :---: (по центру), ---: (справа)
- Чекбоксы задач: - [ ] и - [x]
- Зачёркивание: ~~текст~~
- Emoji-коды: :warning:, :rocket:, :white_check_mark:
- Alert-блоки GitHub:
  > [!NOTE]
  > [!TIP]
  > [!IMPORTANT]
  > [!WARNING]
  > [!CAUTION]
- Блоки кода с подсветкой синтаксиса через ```язык
- Диаграммы Mermaid внутри ```mermaid — GitHub рендерит их нативно
- Базовые сноски [^1] — GitHub их поддерживает
- Якоря на заголовки генерируются GitHub автоматически, кастомные 
  {#id} не нужны. Правило: нижний регистр, пробелы заменены на 
  дефисы, пунктуация убрана, дефисы и подчёркивания сохранены, 
  кириллица сохранена, эмодзи вырезаны. Одинаковые заголовки 
  получают суффиксы -1, -2 в порядке следования — делай заголовки 
  уникальными, чтобы не путать ссылки
- Вставка изображений и бейджей (shields.io) через ![alt](url)
- HTML-теги, если чего-то не хватает в синтаксисе (GitHub 
  санитизирует опасные теги, но <details>/<summary>, <sub>, <sup>, 
  <br>, <img> с атрибутами width — работают)
- Сворачиваемые блоки:
  <details>
  <summary>Заголовок</summary>
  содержимое
  </details>

НЕ используй:
- Синтаксис {#custom-id} для заголовков (не поддерживается GitHub)
- Расширенный синтаксис сносок в стиле Pandoc (базовые [^1] можно)
- Директивы MkDocs/Docusaurus (::: note, admonitions в других 
  форматах)
- Два пробела в конце строки как жёсткий перенос — они невидимы 
  и вырезаются редакторами и форматтерами; используй <br> или 
  разбиение на абзацы

Ничего не выдумывай:
- Автоссылки на issues/PR (#123, GH-123) вставляй ТОЛЬКО если 
  конкретный номер дал я. Не сочиняй номера — они превратятся 
  в ссылки на чужие существующие issue.
- @упоминания вставляй ТОЛЬКО если я дал конкретный логин и 
  человека реально нужно уведомить. Не сочиняй имена пользователей.
- Бейджи вставляй ТОЛЬКО если я дал реальные данные (репозиторий, 
  версию, лицензию, CI). Не подставляй заглушки под видом реальных.

Учитывай, что документ будет открываться ТОЛЬКО на GitHub 
(README, PR-описание, issue, wiki-страница) — не в других 
рендерерах, поэтому GitHub-специфичные фичи использовать можно 
и нужно, если они уместны по смыслу.
