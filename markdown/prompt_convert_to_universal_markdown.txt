Преобразуй прикреплённый/вставленный документ в формат чистого 
Markdown (CommonMark), который корректно отобразится в максимально 
широком наборе рендереров — GitHub, GitLab, PyCharm, VS Code, 
Obsidian. Отдельно учти: при импорте в Notion любой HTML вырезается, 
а якоря заголовков теряются.

Что нужно сделать:
- Сохрани всю структуру, смысл и содержание документа без потерь — 
  не сокращай, не перефразируй текст, меняй только разметку.
- Приведи заголовки к виду # ## ### (убери подчёркивание ===/---, 
  если оно использовалось).
- Замени все платформенно-специфичные конструкции на переносимые:
  - {#custom-id} у заголовков → убери. Если на этот id ссылались 
    только внутри документа — переведи ссылки на автогенерируемый 
    якорь. Если id мог использоваться снаружи, вставь перед 
    заголовком <a id="старый-id"></a>, чтобы внешние ссылки не 
    сломались. На GitHub id получит префикс user-content-, ссылка
    вида #старый-id при этом работает
  - сноски [^1] → перенеси содержимое сноски в текст либо в 
    примечание в скобках
  - alert-блоки GitHub (> [!NOTE] и т.п.) → замени на обычную цитату 
    с текстовой пометкой, например "**Примечание:**"
  - директивы MkDocs/Docusaurus/Pandoc (::: note, admonitions) → 
    разверни в обычный текст с жирным заголовком
  - @упоминания и #123-автоссылки на issues → оставь как обычный 
    текст без спецсинтаксиса
  - emoji-коды (:warning: и т.п.) → замени на unicode-символ либо убери
  - жёсткий перенос через два пробела в конце строки → замени на 
    <br> или на разбиение по абзацам (два пробела невидимы и 
    вырезаются редакторами)
- Таблицы приведи к стандартному виду через |. Выравнивание задавай 
  явно: --- (по умолчанию, слева), :--- (слева), :---: (по центру), 
  ---: (справа) — сохрани то выравнивание, что было в оригинале.
- Списки — через дефис "-", нумерованные — через "1.". Вложенные 
  пункты сдвигай на 4 пробела: так они распознаются и в CommonMark, 
  и в старых парсерах.
- Код оформи тройными обратными кавычками с указанием языка.
- Внутренние ссылки на заголовки пересчитай под автогенерируемые 
  якоря по алгоритму GitHub (GitLab почти идентичен): нижний
  регистр, пробелы заменены 
  на дефисы, пунктуация убрана, дефисы и подчёркивания сохранены, 
  кириллица сохранена, эмодзи вырезаны. Одинаковые заголовки 
  получают суффиксы -1, -2 в порядке следования — учти это, если 
  в документе есть повторяющиеся заголовки.
- HTML оставляй только там, где без него нельзя обойтись, и только 
  базовые теги (<a>, <br>, <sub>, <sup>, <img>, <details>/<summary>).
  Если в оригинале была HTML-таблица без rowspan/colspan и без 
  блочного содержимого в ячейках — переведи её в таблицу через |. 
  Если объединения ячеек или блочное содержимое есть, оставь HTML 
  как есть и отметь это отдельной строкой после документа: 
  переносимого эквивалента у таких таблиц нет.

Верни готовый документ целиком в одном блоке кода, огороженном 
ЧЕТЫРЬМЯ обратными кавычками с пометкой markdown (````markdown), 
чтобы тройные кавычки внутри документа не разорвали блок (если 
в документе уже есть блок из четырёх кавычек — возьми пять). 
Пояснения — только после блока, если они действительно нужны.
