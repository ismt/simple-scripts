Преобразуй прикреплённый/вставленный документ в формат чистого 
Markdown (CommonMark), который корректно отобразится в любом 
стандартном рендерере — GitHub, GitLab, PyCharm, VS Code, Obsidian, 
Notion при импорте.

Что нужно сделать:
- Сохрани всю структуру, смысл и содержание документа без потерь — 
  не сокращай, не перефразируй текст, меняй только разметку.
- Приведи заголовки к виду # ## ### (убери подчёркивание ===/---, 
  если оно использовалось).
- Замени все платформенно-специфичные конструкции на переносимые:
  - {#custom-id} у заголовков → убери, используй автогенерируемый 
    якорь по правилам GitHub (нижний регистр, пробелы → дефисы, 
    пунктуация убрана) или вставь <a id="..."></a> перед заголовком, 
    если нужен предсказуемый якорь
  - сноски [^1] → перенеси содержимое сноски в текст либо в 
    примечание в скобках
  - alert-блоки GitHub (> [!NOTE] и т.п.) → замени на обычную цитату 
    с текстовой пометкой, например "**Примечание:**"
  - директивы MkDocs/Docusaurus/Pandoc (::: note, admonitions) → 
    разверни в обычный текст с жирным заголовком
  - @упоминания и #123-автоссылки на issues → оставь как обычный 
    текст без спецсинтаксиса
  - emoji-коды (:warning: и т.п.) → замени на unicode-символ либо убери
- Таблицы приведи к стандартному виду | ... | с выравниванием :---:.
- Списки — через дефис "-", нумерованные — через "1.".
- Код оформи тройными обратными кавычками с указанием языка.
- Проверь и, если нужно, исправь все внутренние ссылки на заголовки, 
  чтобы они соответствовали новым сгенерированным id.
- HTML оставляй только там, где без него нельзя обойтись, и только 
  базовые теги (<a>, <br>, <sub>, <sup>, <img>, <details>/<summary>).

Верни готовый документ целиком в одном блоке кода с пометкой markdown, 
без дополнительных комментариев вне блока.
