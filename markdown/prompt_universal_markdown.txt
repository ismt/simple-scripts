Сгенерируй документ в формате чистого Markdown (CommonMark), 
который корректно отобразится в максимально широком наборе 
рендереров — GitHub, GitLab, PyCharm, VS Code, Obsidian.
Отдельно учти: при импорте в Notion любой HTML вырезается, 
а якоря заголовков теряются — если документ пойдёт в Notion, 
не полагайся на HTML-вставки и внутренние ссылки на заголовки.

Требования:
- Только базовый синтаксис CommonMark + минимальные GFM-расширения 
  (таблицы, зачёркивание, чекбоксы) — без специфичных для одного 
  движка фич.
- Заголовки — через # ## ###. Setext-заголовки (подчёркивание 
  ===/---) формально валидны в CommonMark, но не используй их: 
  единый ATX-стиль читаемее и не путается с горизонтальной 
  линией ---.
- Внутренние ссылки на заголовки. Единого стандарта якорей нет, 
  поэтому:
  - строй якорь по алгоритму GitHub (GitLab почти идентичен): нижний регистр, 
    пробелы заменены на дефисы, пунктуация убрана, дефисы и 
    подчёркивания сохранены, буквы неанглийских алфавитов 
    (в т.ч. кириллица) сохранены, эмодзи вырезаны;
  - помни про дубликаты: второй и последующие одинаковые 
    заголовки получают суффиксы -1, -2 в порядке следования. 
    Лучше делай все заголовки уникальными, тогда суффиксы 
    не понадобятся;
  - учитывай, что Obsidian ссылается на заголовок по исходному 
    тексту (#Заголовок С Регистром И Пробелами), а Notion якоря 
    при импорте теряет — стопроцентно переносимых внутренних 
    ссылок не существует;
  - НЕ используй синтаксис {#id} (Pandoc/kramdown) и НЕ используй 
    сноски [^1] — они поддерживаются не везде.
- Если нужен предсказуемый якорь, вставляй <a id="..."></a> 
  прямо перед заголовком (работает везде, кроме Notion; на GitHub 
  id получает префикс user-content-, ссылка #... всё равно рабочая), 
  а не полагайся на нестандартные атрибуты.
- HTML — только по необходимости и только базовые теги: 
  <a>, <br>, <sub>, <sup>, <img>, <details>/<summary>. 
  Не используй HTML-таблицы, кастомные блоки-предупреждения 
  (::: note) и другие директивы конкретных статических 
  генераторов (MkDocs, Docusaurus и т.п.), если явно не попрошу.
- Код оформляй тройными обратными кавычками с указанием языка.
- Списки — через дефис "-", нумерованные — через "1.". 
  Вложенные пункты сдвигай на 4 пробела: так они распознаются 
  и в CommonMark, и в старых парсерах (2 пробела корректны 
  по CommonMark, но ломаются в legacy-рендерерах).
- Таблицы — через |. Выравнивание задавай явно: 
  --- (по умолчанию, слева), :--- (слева), :---: (по центру), 
  ---: (справа).
- Не полагайся на жёсткий перенос строки через два пробела 
  в конце строки — они невидимы и вырезаются многими 
  редакторами и форматтерами. Разбивай текст на абзацы пустой 
  строкой, а если перенос внутри абзаца действительно нужен — 
  ставь <br>.
- Проверь, что все внутренние ссылки на заголовки соответствуют 
  реально сгенерированным id.
